# YDB → PostgreSQL

Инструмент для выгрузки YDB и подготовки SQL для PostgreSQL. Работает из командной строки без ИИ. Для запуска через Codex рядом находится скилл с теми же инструментами.

Одна команда создаёт два ZIP: исходный дамп YDB и его конверсию для PostgreSQL. В комплекте есть полностью выдуманная учебная база из четырёх таблиц и 17 строк.

## Быстрый старт без доступа к облаку

Скачайте репозиторий через **Code → Download ZIP** и распакуйте его либо склонируйте:

```bash
git clone https://github.com/introvert-bz/ydb-to-postgres.git
cd ydb-to-postgres
```

Откройте терминал в корне распакованного или склонированного репозитория. Нужен Python 3.9+; сторонние Python-библиотеки не требуются.

```bash
python3 ydb_to_postgres.py demo --output ./work/shop-example
```

В указанной новой папке появятся учебные файлы YDB, результат конвертации и два архива. Команда работает локально без облачных учётных данных.

## Выгрузка настоящей YDB

Нужны YDB CLI и права чтения базы. Для авторизации через существующий профиль нужен также YC CLI с настроенным доступом.

Подставьте свои параметры:

```bash
python3 ydb_to_postgres.py export \
  --database /region/cloud/database-id \
  --endpoint grpcs://your-endpoint:2135 \
  --profile YOUR_YC_PROFILE \
  --output ./private-backups/export-001
```

Вместо `--profile` можно использовать `--iam-token-file /path/to/iam-token`. Сам токен передавайте файлом. Параметры `--ydb-bin` и `--yc-bin` задают расположение CLI; `--dump-timeout` и `--count-timeout` — время ожидания в секундах.

Результат:

```text
private-backups/
  export-001/                 файлы выгрузки и конвертации
  export-001-ydb-original.zip  исходный дамп YDB
  export-001-postgresql.zip    SQL, отчёты и инструкции PostgreSQL
```

Папка результата и имена архивов должны быть свободны. Исходный архив создаётся перед конвертацией и сохраняется, если преобразование невозможно.

Коды завершения:

| Код | Значение |
| --- | --- |
| 0 | Выгрузка, конвертация и предусмотренные проверки завершены |
| 1 | Ошибка; сохранённые файлы нужно проверить перед использованием |
| 2 | Оба архива созданы, но независимые количества строк источника сверены не полностью |

Справка: `python3 ydb_to_postgres.py export --help`.

Настоящие выгрузки могут содержать клиентские данные и секреты. Папки `private-backups/` и `work/`, логи и файлы токенов исключены через `.gitignore`. Для другого места выгрузки задайте своё исключение или используйте путь вне репозитория.

## Конвертация готового дампа

Команда принимает папку выгрузки этого инструментария:

```bash
python3 ydb_to_postgres.py convert \
  --input ./private-backups/completed-copy \
  --database /region/cloud/database-id
```

Входная папка содержит `native-dump/`, `objects.json`, `*.schema.json`, `database.json`, `download-manifest.json` и `source-counts.json`. Результатов конвертации `jsonl/` и `postgres/` в ней быть не должно; рядом не должно быть одноимённых ZIP.

Для повторной конвертации распакуйте исходный архив YDB в новую папку и передайте её через `--input`.

## Загрузка в PostgreSQL

Создайте отдельную пустую PostgreSQL-базу и распакуйте архив PostgreSQL. Выберите один способ загрузки.

**psql:** из папки, содержащей `postgres/`, выполните:

```bash
psql -X --dbname=TARGET_DATABASE --set=ON_ERROR_STOP=1 --file=postgres/load.sql
psql -X --dbname=TARGET_DATABASE --set=ON_ERROR_STOP=1 --file=postgres/verify.sql
```

**pgAdmin Query Tool:** выполните `postgres/pgadmin/00_schema.sql`, затем файлы данных по имени, затем `99_verify.sql`. Каждый файл запускайте целиком. Успешно загруженные части повторно не выполняйте. Порядок восстановления после ошибки описан в `postgres/README.txt` внутри архива.

Инструмент готовит файлы и сам не подключается к PostgreSQL для импорта. Проверка на настоящем сервере PostgreSQL не выполнялась.

## Учебная база shop_demo

Схема и все строки созданы с нуля для вымышленного магазина. Реальные схемы, клиенты, ключи, ACL и идентификаторы облачных ресурсов не использованы.

| Таблица | Строк | Содержимое |
| --- | ---: | --- |
| customers | 3 | Вымышленные покупатели и адреса в домене `.invalid` |
| products | 4 | Товары, целочисленные цены в минимальных денежных единицах, JSON |
| orders | 4 | Заказы с датами UTC и необязательным примечанием |
| order_items | 6 | Позиции заказов с составным первичным ключом |
| **Всего** | **17** | **4 таблицы** |

Логические связи: `orders.customer_id → customers.id`, `order_items.order_id → orders.id`, `order_items.product_id → products.id`. Данные согласованы по этим связям; внешние ключи в SQL не добавляются.

Пример содержит кириллицу, `+`, апостроф, переносы строк, табуляцию, обратную косую черту, NULL, пустую строку, текст `null`, JSON, BOOL, составной ключ и временные метки UTC с микросекундами.

Готовые файлы:

- [Пример в формате дампа YDB](examples/shop-demo-ydb-original.zip).
- [Конверсия примера для PostgreSQL](examples/shop-demo-postgresql.zip).
- [Контрольные суммы SHA256](examples/SHA256SUMS).

Архив YDB собран локальным генератором в формате входных файлов конвертера. Это учебный пример, а не выгрузка из работающей YDB. Количества строк сверены с генератором; восстановление примера в YDB не тестировалось.

## Проверки и ограничения

Перед упаковкой исходного дампа проверяются список таблиц, наличие схемы и данных, порядок и число колонок, количество строк и отсутствие признаков неполной выгрузки. `download-manifest.json` содержит SHA256 исходных файлов; упаковщик повторно сверяет их. Если входной манифест не содержит `native_files`, проверяются структура и количество строк, а отсутствие сверки исходных хешей явно отмечается в `native_validation`.

Конвертация проверяет значения, диапазоны чисел, NULL и уникальность ключей. Каждое поле PostgreSQL COPY сравнивается с нормализованным JSONL. Для архивов проверяются контрольные суммы и CRC ZIP.

Поддерживаются обычные строковые таблицы с простыми именами и типами UTF8, UINT32, INT32, INT64, BOOL, JSON, JSON_DOCUMENT, DATETIME, TIMESTAMP и Optional этих типов. Остальные типы, вложенные пути, TTL, CDC и специальные индексы требуют отдельного проектирования.

YDB допускает NULL в первичном ключе, а PostgreSQL PRIMARY KEY требует NOT NULL. Если NULL встречается в ключе, конвертация останавливается с именем таблицы и колонки; значения не подменяются. Optional-ключ без NULL переносится как NOT NULL. Исходная и целевая nullable-семантика записаны раздельно в `schema-mapping.json`.

Выгрузка через `--avoid-copy` не гарантирует общего согласованного момента всех таблиц. Отдельный COUNT выполняется после выгрузки и может отличаться из-за изменений в работающей базе. JSONB нормализует JSON. Даты и время преобразуются в TIMESTAMPTZ с UTC.

Запуск 10 локальных тестов и генератора примера:

```bash
python3 ydb-to-postgres/scripts/test_workflow.py
python3 tools/build_examples.py --output ./work/demo-build
```

Для каждого запуска генератора укажите новую папку.
