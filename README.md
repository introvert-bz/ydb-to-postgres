# YDB → PostgreSQL

**Готовый скрипт для дампа YDB и конвертации в PostgreSQL. Рядом — Skill для Codex.**

Репозиторий работает без ИИ: одна команда выгружает источник и создаёт оба ZIP.

Скилл выгружает базу через YDB CLI, получает схему из метаданных и готовит два архива: исходный дамп YDB и SQL для PostgreSQL. Предусмотрены загрузка через `psql` и обычный Query Tool в pgAdmin, проверка строк и полей, первичных ключей и SHA256.

## Запуск без ИИ

Установите Python 3.9+ и YDB CLI. Для входа через профиль нужен также YC CLI с уже настроенным доступом. Выполните из корня репозитория, подставив свои параметры:

```bash
python3 ydb_to_postgres.py export \
  --database /region/cloud/database-id \
  --endpoint grpcs://your-endpoint:2135 \
  --profile YOUR_YC_PROFILE \
  --output ./private-backups/export-001
```

Либо замените `--profile` на `--iam-token-file /path/to/iam-token`. Не передавайте сам токен в командной строке. При необходимости укажите `--ydb-bin` и `--yc-bin`. Справка: `python3 ydb_to_postgres.py export --help`.

Результат рядом с новой папкой выгрузки: `export-001-ydb-original.zip` и `export-001-postgresql.zip`. Исходный архив создаётся до конвертации и сохраняется, если типы не поддержаны. Код завершения 0 — конверсия и доступные проверки завершены; 1 — ошибка; 2 — оба архива созданы, но независимые количества строк источника сверены не полностью.

Выгрузка использует права чтения и `--avoid-copy`: общий согласованный снимок всех таблиц не гарантирован. Скрипт не импортирует данные в PostgreSQL. Реальные выгрузки могут содержать секреты и клиентские данные; храните их приватно.

Проверить работу без облака и учётных данных:

```bash
python3 ydb_to_postgres.py demo --output ./work/shop-example
```

Конвертация уже скачанной папки этого инструментария в новом месте:

```bash
python3 ydb_to_postgres.py convert --input ./private-backups/completed-copy --database /region/cloud/database-id
```

Нужны `native-dump/`, `objects.json`, `*.schema.json`, `database.json`, `download-manifest.json` и `source-counts.json`; это не команда для произвольного CSV. Папка не должна содержать результатов предыдущей конвертации.

## Полностью выдуманная база

Схема создана с нуля для учебного магазина. Данные также созданы с нуля; реальные схемы, строки, клиенты, номера, ключи, ACL и идентификаторы облачных ресурсов не использованы.

| Таблица | Строк | Назначение |
| --- | ---: | --- |
| customers | 3 | Вымышленные покупатели, адреса в домене `.invalid` |
| products | 4 | Товары, цены в целых минимальных денежных единицах, JSON |
| orders | 4 | Заказы с датами UTC и необязательным примечанием |
| order_items | 6 | Позиции заказов с составным первичным ключом |
| **Всего** | **17** | **4 таблицы** |

Логические связи: orders.customer_id → customers.id; order_items.order_id → orders.id; order_items.product_id → products.id. Они согласованы в примере, но внешние ключи не добавлены: YDB-конвертер сохраняет первичные ключи и поддерживаемые индексы.

Пример проверяет кириллицу, `+`, апостроф, перенос строки, табуляцию, обратную косую черту, NULL, пустую строку, текст `null`, JSON, BOOL, составной ключ и временные метки UTC с микросекундами.

**Происхождение:** архив YDB создан локальным генератором в формате входных файлов конвертера. Он не является выгрузкой из работающей YDB. Восстановление этого примера в YDB не тестировалось; `source-counts.json` проверен по генератору, а не запросом COUNT к серверу.

## Проверки и воспроизведение

Из корня репозитория:

```bash
python3 ydb-to-postgres/scripts/test_workflow.py
python3 tools/build_examples.py --output ./work/demo-build
```

Папка результата должна быть новой. Генератор сверяет каждое нормализованное поле с выдуманным источником и каждый COPY field с JSONL, проверяет количество строк, ключи, контрольные суммы и CRC ZIP. Архив PostgreSQL содержит `copy-verification.json` и `conversion-report.json`.

Реальный импорт в PostgreSQL не выполнялся: проверка файлов конверсии не равна проверке импорта на сервере. Для проверки загрузки используйте отдельную пустую базу.

## Загрузка примера в PostgreSQL

Распакуйте архив PostgreSQL. Выберите один способ:

- **psql:** `psql -X --dbname=TARGET_DATABASE --set=ON_ERROR_STOP=1 --file=postgres/load.sql`, затем аналогично `postgres/verify.sql`.
- **pgAdmin Query Tool:** выполните `postgres/pgadmin/00_schema.sql`, затем файлы данных по имени, затем `99_verify.sql`.

Каждую часть pgAdmin выполняйте целиком. Успешные части повторно не запускайте. Полные инструкции находятся в `postgres/README.txt` внутри архива.

Дамп настоящей YDB с `--avoid-copy` не гарантирует общего согласованного момента всех таблиц. JSONB нормализует JSON. Типы вне поддерживаемого набора и специальные индексы требуют отдельного проектирования; ограничения описаны в скилле.
