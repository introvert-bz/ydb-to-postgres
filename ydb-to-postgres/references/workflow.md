# Практические особенности

## CLI и авторизация

Проверять `--help` установленной версии перед адаптацией команд. Проверенная комбинация — YDB CLI 2.33 и YC CLI 1.40.0; более новые версии могут менять JSON/флаги. Endpoint брать из параметров базы, не выводить из её идентификатора. Существующий IAM-файл задаётся `download_ydb.py --iam-token-file /private/file`; `--yc-bin` и `--ydb-bin` позволяют использовать локальные установки. В режиме IAM-файла YC нужен только для необязательных облачных метаданных.

Команды чтения: `scheme ls -R -l --format json`, `scheme describe --format proto-json-base64 TABLE`, `tools dump --path . --avoid-copy --ordered --save-partial-result`. Системные объекты `.sys` исключаются. Инвентаризация и DescribeTable сохраняются отдельно. Признаки `incomplete` / `incomplete.csv`, ненулевой код выхода, отсутствие данных таблицы запрещают считать дамп завершённым. Логи хранить приватно и не включать в архив, если они могут содержать детали авторизации.

`scheme --timeout 30s` поддерживается; у scan-запросов некоторых версий суффикс `s` вызывает ошибку разбора. Для scan используется внешний subprocess timeout, а не несуществующий глобальный `--operation-timeout`. Не запускать много сканирований параллельно на рабочей базе. Не выводить клиентские строки и токены при диагностике.

## Типы и ограничения

| YDB | PostgreSQL | Особенность |
|---|---|---|
| Utf8 | TEXT | NULL и пустая строка различаются |
| Uint32 | BIGINT | CHECK 0..4294967295 |
| Int32 / Int64 | BIGINT | Диапазон источника проверяется при чтении |
| Bool | BOOLEAN | Только true/false |
| Json / JsonDocument | JSONB | Нормализация, дубли JSON-ключей могут схлопнуться |
| Datetime / Timestamp | TIMESTAMPTZ | UTC, без потери точности до микросекунд |
| Optional<T> | nullable T | Не делать обязательным по наблюдаемым данным |

Бинарный String, Uint64, Decimal, контейнеры, PostgreSQL-типы YDB и прочие типы требуют отдельного отображения. Не превращать их в TEXT автоматически. JSONB не принимает NUL, недопустимые Unicode и числа вне диапазона PostgreSQL numeric; окончательную совместимость подтверждает импорт. Встроенные скрипты не доказывают всю совместимость с сервером PostgreSQL.

Ключи сохранять из DescribeTable. Для обычного вторичного глобального индекса создаётся B-tree по index_columns; физические настройки, шардинг, TTL, CDC, покрывающие колонки и специальные/векторные индексы не эквивалентны PostgreSQL. Скрипт останавливается на специальных индексах/TTL/CDC; потребность перенести такую семантику обсуждать отдельно. Длинные имена PostgreSQL ограничивает 63 байтами — проверить до генерации, чтобы не получить коллизии.

## Когда метаданные недоступны

UNAVAILABLE, LookupError, недоступный Schemeshard означают сбой доступа к метаданным; это не подтверждение отсутствия строк. Повторять запросы только ограниченно, учитывая просьбу пользователя о количестве попыток.

Если имена известны из приложения или прежней инвентаризации, возможен запасной путь — один полный потоковый `SELECT * FROM \`TABLE\`;` через `table query execute --type scan --format json-base64`. Не ставить LIMIT и не заменять потоковый scan ограничиваемым обычным data-query. Сохранять stdout в `TABLE.partial.jsonl`, переименовывать только после успешного завершения и валидации всех строк. Ошибки и таймауты оставляют неполную таблицу, а не ноль строк. Файлы с секретами защищать правами 0600.

Для сравнения с прежним слепком сравнивать число строк и мультимножество хешей канонизированных строк, независимо от порядка; повторно запрашивать только недостающие/непроверенные таблицы. Прямой SELECT может работать при недоступной инвентаризации, но без схемы нельзя гарантировать полный список таблиц и точные типы. Не выдавать JSONL за штатный полный YDB dump. Конвертер `jsonl_to_postgres.py --input DIR --schema VERIFIED.sql --output NEWDIR` принимает такой JSONL только при наличии проверенной схемы; `--allow-partial` включать лишь при явной потребности пользователя и честно обозначать неполноту.

Облачная управляемая резервная копия не обязательно имеет API прямой загрузки. Восстановление во временную БД и экспорт в S3 требуют отдельных ресурсов/прав; их не запускать автоматически вместо чтения. Официальная документация при необходимости: https://ydb.tech/docs/ru/reference/ydb-cli/export-import/ .

## Результат и сбои

Новая папка на каждый запуск: инструменты отказываются перезаписывать результат конвертации. Нативный архив остаётся пригодным независимо от успеха PostgreSQL. При неуспешной конвертации сохранить диагностику и исходные данные, продолжать в новой папке или убрать только подтверждённые промежуточные результаты.

Отдельный COUNT выполняется после дампа, поэтому отличия могут означать изменения в живой БД. Нельзя объявлять совпавший COUNT доказательством общего момента между таблицами. В манифестах указывать время и `common_snapshot_across_tables: false`.

PostgreSQL COPY импорт быстрее и требует psql; pgAdmin Query Tool принимает готовые INSERT SQL без `\ir` и COPY STDIN. Каждая часть INSERT имеет свою транзакцию; после ошибки ROLLBACK и повтор только неуспешной части. Уже успешные части повторно не запускать. При неопределённом результате COMMIT сначала проверить ключи/количество строк или использовать новую пустую базу. Итоговая проверка считает строки; реальную загрузку и прикладную совместимость отмечать отдельно.
