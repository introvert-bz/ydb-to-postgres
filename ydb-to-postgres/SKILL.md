# YDB → PostgreSQL

По умолчанию результат — два ZIP: исходный штатный дамп с метаданными и PostgreSQL SQL с инструкцией для psql и обычного Query Tool в pgAdmin. Схему получать из самой YDB; предоставленная пользователем схема необязательна. Выполнять через консоль, если пользователь не выбрал другой способ.

## Подключение и выгрузка

Установить полный путь базы, endpoint, существующий пользовательский профиль YC или файл IAM-токена, расположение CLI и новую папку результата. Использовать доступные в сессии параметры, не просить их повторно. Найти `yc` и `ydb` через PATH; при отсутствии проверить локальные установки в рабочей папке и `~/ydb/bin`. Не включать данные, учётные записи и секреты текущего проекта в сам навык.

Пользовательский профиль позволяет обойтись без сервисного аккаунта. Не читать и не выводить целиком конфигурацию YC: там могут быть ключи других профилей. IAM-токен передавать через `--iam-token-file`, а не `--yc-token-file`. Скрипт создаёт приватный временный файл и удаляет его при завершении. При устаревшей авторизации использовать разрешённый пользователем способ входа; `--no-browser` предотвращает неожиданный запуск браузера. Если вход требует участия пользователя, сообщить конкретную причину.

Пример: переменная `SKILL` обозначает абсолютный каталог этого навыка; подставить реальные параметры вместо заглушек.

```bash
python3 "$SKILL/scripts/download_ydb.py" \
  --database /region/cloud/database-id \
  --endpoint grpcs://endpoint:2135 \
  --profile USER_PROFILE \
  --output /absolute/path/new-export
python3 "$SKILL/scripts/package_copy.py" raw /absolute/path/new-export
python3 "$SKILL/scripts/native_to_postgres.py" /absolute/path/new-export \
  --database /region/cloud/database-id
python3 "$SKILL/scripts/verify_copy.py" /absolute/path/new-export
python3 "$SKILL/scripts/package_copy.py" postgres /absolute/path/new-export
```

Архив исходного дампа создавать до конвертации: неподдерживаемый тип не должен лишать пользователя копии. Если независимый COUNT недоступен или отличается, сохранять честный статус в `source-counts.json`, объяснить ограничение; не выдавать такую копию за полностью сверенную. Не повторять запросы бесконечно: один проход по таблицам, затем адресный повтор только по необходимости в рамках запроса пользователя. Ограничение «по одному разу» обязательно.

`--avoid-copy` не создаёт временных таблиц в источнике и подходит для прав чтения, но не гарантирует общего согласованного момента всех таблиц. Если пользователю нужен именно согласованный снимок, сначала согласовать другой механизм; не обещать его для этого режима. Не создавать бакеты, сервисные аккаунты, ресурсы или восстанавливать базу как неявную часть выгрузки.

## Конвертация и проверки

Скрипты используют только стандартную библиотеку Python 3.9+. Ожидают обычные строковые таблицы с простыми именами без вложенных путей. Поддерживают UTF8, UINT32, INT32, INT64, BOOL, JSON, JSON_DOCUMENT, DATETIME, TIMESTAMP и Optional этих типов. Для прочих типов, вложенных путей и специальных индексов изучить метаданные, явно спроектировать и протестировать отображение. Не угадывать типы, ключи и связи по нескольким значениям. При невозможности конвертации выдать исходный архив и причину.

Сверять порядок колонок DescribeTable и scheme.pb, NULL, диапазоны чисел, поля каждой строки, уникальность составных первичных ключей, SHA256 и количество строк. В штатном CSV `+` означает пробел, `%2B` — плюс; голое `null` отличается от строки `"null"`. Не декодировать обычным CSV с потерей кавычек. Не изменять исходные файлы.

`verify_copy.py` сравнивает каждое поле COPY с нормализованным JSONL. Упаковщик PostgreSQL запускает эту проверку ещё раз и создаёт обычные INSERT-файлы для pgAdmin, SHA256-манифест и проверку количества строк. Проверить CRC ZIP. JSONB нормализует JSON; часовые пояса сохраняются как TIMESTAMPTZ с UTC. Поле даты должно оставаться датой, а не локальным временем без зоны.

Импортировать в отдельную пустую PostgreSQL только когда пользователь просит сам импорт. Подготовка архивов сама по себе не разрешает загрузку в существующую базу. Не называть генерацию SQL проверенным импортом: для такого утверждения нужен реальный успешный запуск PostgreSQL. Для pgAdmin использовать `pgadmin/00_schema.sql`, части в порядке имён и `99_verify.sql`; PSQL Tool не требуется.

В финале дать ссылки на два архива, число таблиц/строк и существенные ограничения проверки. Для ошибок метаданных, частичной выгрузки, особенностей типов и продолжения после сбоев прочитать [references/workflow.md](references/workflow.md).
